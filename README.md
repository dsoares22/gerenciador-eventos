# 📅 Gerenciador de Eventos

API REST em Java com Spring Boot para cadastrar eventos e organizá-los por categoria. Os dados ficam em um banco PostgreSQL, a API é documentada com Swagger, e há telas simples em HTML, CSS e JavaScript para usar o sistema pelo navegador.

▶️ **Link do vídeo:** https://drive.google.com/file/d/1SnRDgIABvvoKSrBCZ2j-xQ1OymWKvg6t/view?usp=sharing

## ✨ Funcionalidades

- Cadastrar, listar, buscar, editar e excluir categorias e eventos.
- Cada evento pertence a uma categoria (uma categoria pode ter vários eventos).
- Filtrar eventos por título, categoria ou período.
- Regras de negócio com mensagens de erro em português.
- Documentação e testes da API pelo Swagger.
- Telas web conectadas à API (ponto extra).

## 🧩 Como a API funciona

- Camadas: o `Controller` recebe a requisição, o `Service` aplica as regras de negócio e o `Repository` acessa o banco.
- DTOs: a API recebe e devolve DTOs (`CategoryRequest`, `CategoryResponse`, `EventRequest` e `EventResponse`) em vez das entidades do banco. A conversão é feita no Service.
- Relacionamento: `Category` tem `@OneToMany` com `Event`, e `Event` tem `@ManyToOne` com `Category`.
- Respostas: os controllers usam `ResponseEntity` para devolver o status HTTP certo em cada operação.
- Erros: o `GlobalExceptionHandler` (`@RestControllerAdvice`) trata os erros em um só lugar e devolve sempre `{ "message": "..." }`.

## 🗄️ Banco de dados

São duas tabelas: `category` e `event`. Cada evento guarda o id da sua categoria (`category_id`).

```sql
CREATE TABLE category (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    description VARCHAR(255)
);

CREATE TABLE event (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    description VARCHAR(100),
    date DATE NOT NULL,
    time TIME NOT NULL,
    location VARCHAR(100) NOT NULL,
    category_id BIGINT NOT NULL,
    CONSTRAINT fk_event_category
        FOREIGN KEY (category_id) REFERENCES category (id)
);
```

## 🚀 Como executar

### Requisitos

- Java 25 (JDK)
- PostgreSQL e pgAdmin
- IntelliJ IDEA (opcional, para o backend)
- VS Code com a extensão Live Server (para o frontend)

O Maven não precisa estar instalado, porque o projeto usa o Maven Wrapper (`mvnw`).

### 1. Clonar o projeto

```bash
git clone https://github.com/dsoares22/gerenciador-eventos.git
cd gerenciador-eventos
```

### 2. Criar o banco de dados

1. Abra o pgAdmin e conecte ao servidor PostgreSQL.
2. Clique com o botão direito em Databases → Create → Database, informe o nome `gerenciador_eventos` e salve.
3. Selecione o banco criado, abra Tools → Query Tool, cole o script da seção Banco de dados (acima) e clique em Execute (F5).
4. Confira em Schemas → public → Tables se as tabelas `category` e `event` foram criadas.

### 3. Configurar a conexão com o banco

A conexão já aponta para `jdbc:postgresql://localhost:5432/gerenciador_eventos`. Falta informar o usuário e a senha:

1. Na pasta `backend/src/main/resources/`, faça uma cópia do arquivo `application-local.properties.example` com o nome `application-local.properties`.
2. Preencha com o usuário e a senha do seu PostgreSQL:

   ```properties
   spring.datasource.username=postgres
   spring.datasource.password=sua_senha
   ```

3. Se o seu PostgreSQL usar outra porta, adicione também a URL nesse arquivo:

   ```properties
   spring.datasource.url=jdbc:postgresql://localhost:PORTA/gerenciador_eventos
   ```

O arquivo `application-local.properties` está no `.gitignore`, para que as credenciais não sejam enviadas ao repositório.

### 4. Executar o backend

**Pelo IntelliJ IDEA:**

1. Abra a pasta `backend` em **File → Open** e aguarde o download das dependências.
2. Execute a classe `GerenciadorEventosApplication`, em `src/main/java/br/com/gerenciadoreventos/`.

**Pelo terminal:**

```bash
cd backend
./mvnw spring-boot:run        # macOS / Linux
mvnw.cmd spring-boot:run      # Windows
```

A aplicação terminou de iniciar quando aparecer no console a mensagem `Started GerenciadorEventosApplication`. A API fica disponível em `http://localhost:8080`.

Se aparecer um erro de autenticação no banco, confira o usuário e a senha do passo 3. Se aparecer `Schema-validation`, confira se o script SQL foi executado.

### 5. Testar a API pelo Swagger

Com o backend rodando, acesse **http://localhost:8080/swagger-ui.html**.

1. Clique no endpoint que quer testar.
2. Clique em Try it out.
3. Preencha os parâmetros ou o JSON (o Swagger já mostra um exemplo).
4. Clique em Execute. O status e a resposta aparecem logo abaixo.

### 6. Executar o frontend

O backend precisa estar rodando.

Pelo VS Code:

1. Abra a pasta `frontend` no VS Code.
2. Instale a extensão Live Server, se ainda não tiver.
3. Clique com o botão direito em `index.html` → Open with Live Server.

Ou pelo terminal (com Python instalado):

```bash
cd frontend
python3 -m http.server 5500
```

Depois acesse http://localhost:5500.

São duas telas:

- Eventos (`index.html`): cadastrar, editar, excluir e filtrar eventos.
- Categorias (`categorias.html`): cadastrar, editar e excluir categorias.

Quando a API devolve um erro, a mensagem aparece em um alerta na tela.

## 🔗 Endpoints

| Método | Categorias | Eventos | Sucesso |
|---|---|---|---|
| GET | `/api/categories` | `/api/events` | 200 |
| GET | `/api/categories/{id}` | `/api/events/{id}` | 200 |
| POST | `/api/categories` | `/api/events` | 201 |
| PUT | `/api/categories/{id}` | `/api/events/{id}` | 200 |
| DELETE | `/api/categories/{id}` | `/api/events/{id}` | 204 |

**Filtros de eventos** (`GET /api/events`), usados um de cada vez:

| Parâmetro | Exemplo |
|---|---|
| `title` | `/api/events?title=show` |
| `categoryId` | `/api/events?categoryId=1` |
| `startDate` e `endDate` | `/api/events?startDate=2026-12-01&endDate=2026-12-31` |

## 📝 Exemplos de uso

### Cadastrar uma categoria

`POST /api/categories`

```json
{
  "name": "Musical",
  "description": "Shows e apresentações"
}
```

Resposta **201 Created**:

```json
{
  "id": 1,
  "name": "Musical",
  "description": "Shows e apresentações"
}
```

### Cadastrar um evento

`POST /api/events`. A data usa o formato `aaaa-mm-dd`, e o horário, `hh:mm`.

```json
{
  "title": "Show de Rock",
  "description": "Banda local",
  "date": "2026-12-10",
  "time": "20:00",
  "location": "Praça Central",
  "categoryId": 1
}
```

Resposta **201 Created**:

```json
{
  "id": 1,
  "title": "Show de Rock",
  "description": "Banda local",
  "date": "2026-12-10",
  "time": "20:00",
  "location": "Praça Central",
  "category": {
    "id": 1,
    "name": "Musical",
    "description": "Shows e apresentações"
  }
}
```

### Exemplos de erro

| Situação | Status | Resposta |
|---|---|---|
| Categoria com nome repetido | 409 | `{ "message": "Já existe uma categoria com esse nome" }` |
| Excluir categoria que tem eventos | 409 | `{ "message": "Não é possível excluir uma categoria que possui eventos associados" }` |
| Evento com data no passado | 400 | `{ "message": "A data e o horário do evento não podem estar no passado" }` |
| Evento sem título | 400 | `{ "message": "O título é obrigatório" }` |
| Buscar id que não existe | 404 | `{ "message": "Evento não encontrado" }` |

## 📏 Regras de negócio

As regras ficam na camada de Service:

1. Categoria sem nome repetido: não é possível cadastrar ou renomear uma categoria com um nome que já existe, mesmo com maiúsculas ou espaços diferentes → 409.
2. Categoria com eventos não pode ser excluída: primeiro é preciso excluir ou mudar a categoria dos eventos → 409.
3. Evento não pode estar no passado: a data e o horário precisam ser futuros, no cadastro e na edição → 400.
4. Filtro por período válido: é preciso informar as duas datas, e a data inicial não pode ser depois da final → 400.

Além disso, os campos obrigatórios e o tamanho máximo dos textos são validados nos DTOs (`@NotBlank`, `@NotNull`, `@Size`) → **400**, e um evento só pode usar uma categoria que exista → **404**.

## ⚠️ Status HTTP usados

| Status | Quando acontece |
|---|---|
| 200 OK | Consulta ou atualização feita |
| 201 Created | Registro cadastrado |
| 204 No Content | Registro excluído |
| 400 Bad Request | Dados inválidos ou regra de data/período violada |
| 404 Not Found | Categoria ou evento não encontrado |
| 409 Conflict | Nome repetido ou exclusão de categoria com eventos |
